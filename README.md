# BDSnowflake — лабораторная работа №1

Нормализация исходных данных в аналитическую модель «Снежинка» (Snowflake).

## О чём работа

Я взял исходные данные о продажах зоотоваров (покупатели, продавцы, товары,
магазины, поставщики, питомцы) — 10 CSV-файлов по 1000 строк, всего 10 000 записей —
и трансформировал их в аналитическую модель «снежинка».

В центре модели — таблица фактов `fact_sales` с метриками продаж.
Вокруг — измерения (покупатели, продавцы, товары, магазины, поставщики,
питомцы, даты), часть которых ссылается на справочники 2-го уровня
(категории питомцев, категории товаров, бренды товаров). Именно это
разветвление и превращает модель из «звезды» в «снежинку».

## Модель данных

Таблица фактов:
- `fact_sales` — продажи: `sale_quantity`, `sale_total_price`, `product_quantity`
  и внешние ключи на все измерения.

Измерения 1-го уровня:
- `dim_customer` — покупатели
- `dim_seller` — продавцы
- `dim_product` — товары
- `dim_store` — магазины
- `dim_supplier` — поставщики
- `dim_pet` — питомцы покупателей
- `dim_date` — календарь дат продаж

Измерения 2-го уровня (нормализация «снежинки»):
- `dim_pet_category`  ← ссылается `dim_pet`
- `dim_product_category` ← ссылается `dim_product`
- `dim_product_brand` ← ссылается `dim_product`

Схема связей:

    fact_sales
      ├── dim_customer ────┐
      ├── dim_seller       │
      ├── dim_product ─────┼── dim_product_category
      │                    └── dim_product_brand
      ├── dim_pet ─────────── dim_pet_category
      ├── dim_store
      ├── dim_supplier
      └── dim_date

## Как запустить

### Способ 1 — через Docker (рекомендуется)

Требуется установленный Docker Desktop: https://www.docker.com/products/docker-desktop/

В корне проекта выполнить:

    docker compose up -d

PostgreSQL поднимется на `localhost:5432`:

| Параметр | Значение |
|---|---|
| Database | `snowflake_lab` |
| User | `student` |
| Password | `student` |

Все SQL-скрипты из папки `sql/` выполнятся автоматически
при первом старте контейнера в порядке `00 → 01 → 02`.

Важно: если у вас уже установлен локальный PostgreSQL на порту 5432,
замените в `docker-compose.yml` строку `"5432:5432"` на `"5433:5432"`
и подключайтесь к порту 5433.

Остановить и удалить контейнер вместе с данными:

    docker compose down -v

### Способ 2 — вручную через DBeaver

1. Создать базу данных `snowflake_lab` в своём PostgreSQL.
2. Выполнить `sql/00_load_mock_data.sql`:
   - либо заменить пути в `\copy` на локальные,
   - либо импортировать CSV-файлы через мастер импорта DBeaver.
3. Выполнить `sql/01_ddl.sql` — создаст измерения и таблицу фактов.
4. Выполнить `sql/02_dml.sql` — заполнит их данными из `mock_data`.

## Проверка результата

После запуска любым способом выполнить:

```sql
SELECT COUNT(*) FROM mock_data;                    -- 10000
SELECT COUNT(*) FROM fact_sales;                   -- 10000
SELECT COUNT(DISTINCT sale_id) FROM fact_sales;    -- 1000
```

- В `mock_data` — ровно 10 000 строк (10 файлов × 1000 строк).
- В `fact_sales` — ровно 10 000 продаж.
- `sale_id` уникален только в пределах одного CSV-файла, поэтому различных
  значений всего 1000 (это ожидаемое поведение исходных данных;
  первичным ключом в `fact_sales` служит `fact_id`).
